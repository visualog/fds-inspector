# 검사 목록·메모 UI 계층 정리 — 1.0.6

## 사용자 지적과 수정

1. ‘메모 추가’가 이중 버튼처럼 보임: 메모 컨테이너의 배경·패딩을 제거하여 실제 버튼 표면 하나만 남겼다. 저장된 메모, 입력, 수정·삭제 동작은 유지한다.
2. 검사 목록에서 동일한 10px 항목을 구분하기 어려움: 그룹 제목에 ‘상단 패딩 10px’, ‘하단 패딩 10px’처럼 속성과 값을 함께 표시한다. 판정은 아래 보조 줄로 구분한다.
3. 하위 요소가 어떤 상위 정보에 속하는지 불명확함: 헤더와 하위 목록을 같은 wrapper·표면으로 묶고, 하위 목록을 들여쓴다. 그룹 사이 간격은 `--spacing-2`의 8px fallback을 사용한다. 자식 항목의 반복 카드 배경은 제거하고 선택 항목의 전체 노란 면 강조는 낮춘다.

펼친 헤더의 `aria-controls`와 하위 목록의 `aria-labelledby`를 연결한다. 메모 버튼과 목록의 키보드 포커스 표시를 유지·보강한다. 검사 판정 규칙·패키지 매핑·대상 앱 코드·Figma·Git 원격은 변경하지 않았다.

## 변수 예외

FDS semantic surface와의 대응을 검증하지 못한 오버레이 전용 그룹·선택 표면은 `#fds-root`에 로컬 변수 `--fds-local-group-surface`, `--fds-local-selection-surface`로 선언했다. 로컬 포커스 변수 `--fds-local-focus-ring`은 기존 `--fds-brand`를 참조한다. 승인된 FDS semantic 대응이 정해지면 이 변수 정의를 교체할 수 있다.

## 자동 검증

새 요구의 실패를 먼저 확인한 뒤 수정했다. 제목의 속성 표시, 펼친 그룹의 자식 포함·ARIA 연결, 접힌 그룹의 자식 숨김, 메모의 단일 표면, 하위 행의 중립 배경과 키보드 포커스를 검사한다. 이전 ‘값만 표시’ 계약 테스트는 새 요구에 맞게 변경했다.

`npm test`: 323개 성공, 실패 0개. `npm run build:extension`: 1.0.6, runtime 파일 51개. `git diff --check`: 통과.

Ego의 별도 탭에서 실제 `/ui-system?view=fds&audience=service` 페이지에 테스트용 런타임을 주입하여 확인했다. 상단·하단 패딩 10px의 서로 다른 제목, 헤더와 자식의 ARIA 연결, 펼치기와 Enter 접기, 메모 입력 포커스·취소를 확인했다. CSS 우선순위 문제를 추가로 수정한 뒤 비선택 자식의 투명 배경, 선택 표면 `rgba(255, 187, 61, 0.14)`, 메모 컨테이너의 투명 배경·0px 패딩, 제목의 가로 넘침 없음을 확인했다. 사용자 탭은 변경하지 않았고 QA 탭은 종료했다.

실제 Chrome 설치 상태의 검증과 구분해야 한다. 브라우저 QA는 사용자 탭을 변경하지 않고 별도 Ego 탭에 테스트용 런타임을 주입한다. 설치된 확장앱에서는 Chrome의 확장앱 새로고침 후 대상 페이지도 새로고침하여 다시 검사해야 한다.
