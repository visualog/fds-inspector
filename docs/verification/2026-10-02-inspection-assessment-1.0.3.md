# FDS Inspector 1.0.3 — 값과 작성 근거 분리

## 변경

- 각 검사 항목의 `metadata.assessment`에 value(aligned/outside/unknown), usage(literal/variable/expression/unknown), origin(unknown), authored 및 status를 기록한다.
- 등록값의 직접 작성은 recommendation, 미등록 직접 작성은 mismatch 후보, 작성값 미확인 또는 등록되지 않은 변수/계산식은 review로 분류한다.
- 기존 메시지는 호환성을 위해 유지하며 화면의 톤은 구조화된 판정을 우선한다. 토큰 사용이 확인된 정상 항목은 문제 목록에 넣지 않는다.
- 결과를 `FDS 불일치 후보`와 `권장·확인 사항`으로 분리한다. 후자는 전환 권장/확인 필요 건수를 별도로 표시하고 목록에서도 상태를 표시한다.
- 상단 큰 숫자는 패턴 수, 설명의 건수는 개별 검사 항목 수이다. 한 요소에 여러 검사가 있을 수 있다. 툴바는 중복 제거된 검토 대상 요소 수이다.
- 같은 값의 recommendation/review를 별도 그룹으로 유지한다. 저장 리포트 항목에도 판정 상태를 유지한다.
- 긴 요약 설명을 줄바꿈하고 두 요약 카드의 높이를 콘텐츠에 맞춰 함께 늘린다.

## 검증

- `node --test`: 6px 직접 작성, 7px 직접 작성, 출처 미확인, 미등록 변수, 토큰 정상 사용, 상태별 그룹 분리, 리포트 상태, 툴바 문구, 요약 줄바꿈 회귀 검사 포함.
- Ego agent-owned 탭의 실제 `/ui-system?view=fds&audience=service`에서 최신 런타임을 주입해 라운드 review 표시를 확인했다.
- 작은 브라우저 fixture에서 7px가 불일치 후보, 6px 직접 작성이 토큰 전환 권장, FDS 변수 사용이 정상임을 확인했다.
- 브라우저 검증은 테스트용 chrome runtime/storage shim을 사용하는 주입 검증이다. 사용자가 설치한 확장앱 재로드 검증이 아니다. 기존 사용자 탭/저장 데이터는 수정하지 않았다.

## 한계

- DOM 클래스 이름이나 값만으로 앱/공식 fe-ui 출처를 증명할 수 없다. `origin`은 unknown으로 유지한다. 공식 라이브러리 자동 면제는 구현하지 않았다.
- 권장 항목도 앱 수정 대상임을 뜻하지 않는다. 공식 컴포넌트 내부 값이라면 라이브러리 소유자가 판단해야 한다. 상세 안내에서 소유 출처 미확인을 표시한다.
- CSSOM이 작성 근거를 제공하지 않으면 실제 정상 항목도 review에 남을 수 있다. cross-origin stylesheet, 복합 계산식 등은 추가 근거가 필요하다.
- 저장 리포트의 기존 전체 요약 열 이름은 호환성을 위해 유지되며 개별 항목의 새 상태가 정확한 판정 기준이다.
- 앱 코드, Figma, 외부 패키지, Git 원격 저장소는 변경하지 않았다.

## 사용

`dist/fds-inspector`를 Chrome 확장앱 관리 화면에서 다시 로드한 후 검사 페이지를 새로고침하고 재검사한다. 결과 상단의 확장앱 버전이 1.0.3인지 확인한다.
